# Suzu 候选排序与字体设置

应用内置 Suzu-2.4 Q8_0（约 44 MB），默认开启。位置：设置 → 虚拟键盘 → Suzu 候选排序。
同页可调整键盘字体（12–32 dp，默认 20）和键盘候选字体（12–32 sp，默认 18）。
返回输入框后使用新字号；字母、数字、符号及按键角标按比例调整，候选栏与展开候选使用同一字号。
悬浮候选窗口继续使用原有“候选窗口”字体设置。

## 排序范围

- Fcitx 拼音生成候选后，给前 10 项中与原首选字数相同的中文候选打分。保留候选池，只改变顺序。
- 模型使用光标前最近至多 30 个字符。通过 InputConnection 读取；排除正在编辑的 composing 文本。
- 词表外候选、无上文、加载失败、特殊模式、笔画过滤和预测联想保留原序。
- 分数为候选字符的对数概率和，加入 `-0.3 × 原始名次` 先验。
  新首选须比原首选高至少 2.5，否则保留原首选，仅调整后续项。
- 模型由独立工作线程持有，2 个推理线程。Fcitx 最多等待 40 ms；超时保留原序，不在稍后突然改变当前列表。
- 修改的是原生 CommonCandidateList 中的实际 CandidateWord 顺序，因此点击、空格、数字键、翻页和候选操作共享索引，原选词回调和学习逻辑保留。
- 不读取其他应用的屏幕，不生成新候选，不采集训练数据。排序模块不调用网络；应用仅为检查和下载更新联网。
- 密码、数字、电话和禁止个性化学习的输入框不提供上下文；失焦时清除上下文与模型缓存。

第一版的同字数限制是保守范围，并不等价于拼音切分或完整输入覆盖判断。
例如 `xian` 的“现”和“西安”不会跨组比较。后续可在引擎公开完整覆盖和候选来源信息后扩展。
实际收益与延迟须在个人使用和手机上评估；模拟器测试不代表手机性能。

## 输入与评测协议 v1

本节先定义任务与验收口径。当前应用尚未实现训练样本采集或端到端拼音模型，本节不代表这些能力已经上线。

### 任务边界

| 系统 | 实际输入 | 输出 | 当前状态 |
| --- | --- | --- | --- |
| Fcitx 拼音引擎 | 当前原始拼音缓冲区、输入模式、引擎词典和用户词典 | 中文候选 | 已接入 |
| Suzu 排序器 | 有限汉字前文、引擎提供的汉字候选 | 同一候选池的新顺序 | 已接入；当前拼音没有传入模型 |
| 拼音到汉字生成模型（P2C） | 有限前文、包含错拼或未完成音节的原始拼音缓冲区 | 中文候选、覆盖范围与分数 | 待离线对照 |

不能假定语言模型天然支持原始拼音、简拼或错拼。这些能力取决于训练数据、输入表示和解码约束，需要逐项验证。
当前 Suzu 即使把某个词排得很好，也不能恢复候选池中不存在的词。

### 输入与标签

- 采集端保留按键、删除、插入、光标移动和组合输入边界；模型通常消费当时未上屏的拼音缓冲区，不必直接消费全部按键历史。
- 输入包括决策时已经存在的有限前文、原始拼音缓冲区、缓冲区光标位置，以及全拼/双拼等模式。前文不得包含正在组合的候选或之后才出现的文字。
- 不先把错拼修成标准拼音再评测。标准拼音可作为辅助标注；从答案反推的标准拼音不能替代真实输入。
- 例如前文“我明天去”、原始输入 `beijng`、确认目标“北京”，应以 `beijng` 做输入；不能把它替换成 `beijing` 后声称通过了错拼测试。
- `bj` 可能是简拼，`beij` 可能只是还没打完，均不能自动标为错误。错拼需区分漏键、多键、替换、相邻字母交换和读音混淆。
- 标签使用人工确认的可接受中文答案集合；允许多解。自然使用中的点击和空格接受先视为行为记录，不能直接等同于唯一正确答案。
- 每个候选保留稳定标识、文本、原序、展示序、可消费的原始输入区间和来源。覆盖范围不同的候选不直接当作同一转换任务比较。
- 以上是待实现的采集要求；当前 Android 候选接口仍需补齐稳定标识与完整覆盖信息。
- 整段转换与续写分开评测。转换候选只解释声明覆盖的输入；超出覆盖范围的补全必须明确标记为续写。

### 固定对照与数据划分

1. 首先比较 Fcitx 原排序、当前发行版 Fcitx + Suzu，以及待测方案。固定原始输入、上下文、引擎配置、词典及用户词典快照。
2. **排序对照**复用同一个冻结候选池，判断分数、先验和首选门控的作用；候选池缺失的答案不能从样本中悄悄删除。
3. **端到端对照**允许不同方案生成自己的候选池，在相同输入、输出覆盖范围和时间预算下比较。包含解析、纠错、生成、排序与回退的实际显示结果。
4. 测试集分别覆盖正确全拼、简拼/混拼、未完成输入、真实错拼、短/无上文、专名与中英混输；额外保留本来就正确的输入，检查是否被过度纠正。真实错误与人工合成错误分开报告。
5. 主统计单位是一轮组合输入的确认决策；逐键轨迹另作辅助评测，不能把一个词的多个拼音前缀当作多个独立样本刷高样本量。
6. 训练、调参和测试按时间及会话分组划分；同一组合输入和同源改写不能跨分区。所有个人词频、纠错记忆等特征只使用决策之前的数据。
7. 人工确认题测答案质量，自然行为记录测对用户选择的拟合；后者存在位置偏差，不能单凭离线重排推断节省了多少实际按键。

### 指标与验收

| 指标 | 固定口径 |
| --- | --- |
| 候选覆盖率 @10 | 可接受答案至少一个出现在前 10 个候选中的决策比例；候选消耗相同输入范围 |
| 首选、前 3、前 5 命中率 | 可接受答案出现在相应位置的决策比例；同时报告全部样本与可重排子集 |
| 字符错误率 CER | 仅对固定主参考、覆盖同一输入范围的对齐题计算字符编辑距离，总距离除以参考字符总数；语义多解题以答案集合命中率为主，不能只凭 CER 判错 |
| 首选改善与误改 | 分别统计“原首选错误、现首选正确”及“原首选正确、现首选错误”；同时给出总样本分母与原首选正确样本分母 |
| 纠错与过度纠错 | 错拼题恢复正确答案的比例，以及正确输入被错误改写的比例；按错误类型分层 |
| 响应时间 | 真机按键到候选可见的 p50/p95/p99，冷启动与热运行分开；模型计算时间另列 |
| 可靠性 | 超时、回退、错上屏、候选迟到后跳变、崩溃，以及密码/禁止个性化字段的禁采结果 |
| 实际输入成本 | 受控输入任务或经授权的分组试验中的选词、翻页、退格次数及完成时间；不从静态候选名次直接推算 |

- 报告包含有效决策数、独立会话数、日期跨度、分层结果和坏例；按会话/日期进行配对统计，不能只给训练 loss 或几个成功例子。
- 排序器当前只改变前 10 项中的同字数中文候选，必须同时报告这部分的覆盖与收益，以及对全部输入的净影响。
- 升级条件：主测试集的配对首选收益具有可靠的正向证据，关键场景未出现无法接受的退步，误改首选的坏例完成审查；证据不足时结论为“待验证”。
- 第一轮真机实验暂以热运行 p95 额外开销不超过 10 ms、超时率不超过 1% 作为工程预算，错上屏和敏感字段违规为零容忍。这是项目试验目标，不是业界标准或当前实测结果；如需修改，须在开发集上确定并在正式测试前冻结。
- 当前 40 ms 等待上限只约束原生排序等待，不等于按键到界面显示的总延迟。模拟器耗时不用于真机验收。
- 新版模型先离线回放，再进行可回退的真机试用。现有 `SuzuRerankingTest` 只验证模型/排序/选词链路，不能证明候选准确率提升。

### 待比较的公开 P2C 实现

- [Transformers4IME / PinyinGPT](https://github.com/VisualJoyce/Transformers4IME)：ACL 2022、GPT-2 路线的历史研究基线，有代码及预训练模型入口。论文假设已提供正确的拼音切分，主实验研究正确全拼与纯首字母简拼，切分集成和混拼被列为后续工作；仓库另列有混合训练模式，不能把代码选项等同于经过论文验收的能力。论文未采用实际按键成本或人工评价，也不能证明原始连续字母错拼和手机实时链路已经可用。仅作为条件受限的历史对照，不作为当前手机集成的优先方案。
- [Duyu/Pinyin2Hanzi-Transformer](https://huggingface.co/Duyu/Pinyin2Hanzi-Transformer)：公开约 62M 参数权重和推理代码，模型卡标注长度限制 14，输入需遵循其音节表示；尚未验证原始错拼、候选列表与手机延迟。
- 两者目前仅是对照候选，未集成、未在本项目运行，也没有替换现有输入引擎。

方法参考：[PinyinGPT 论文](https://aclanthology.org/2022.acl-long.133/)、[拼音错拼纠正研究 KNPTC](https://arxiv.org/abs/1805.00741)、[用户点击的位置偏差](https://www.microsoft.com/en-us/research/publication/unbiased-learning-rank-biased-feedback/)、[按时间划分评测](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)。

## 构建

```powershell
git submodule update --init --recursive
./scripts/fetch-suzu.ps1
./gradlew.bat :app:assembleDebug -PbuildABI=arm64-v8a
```

模型下载固定 Hugging Face revision `b166ed00f744a3a8f68f7b1b8980a76c80ac9f25`，
模型及词表的 SHA-256 均由脚本核对。模型不提交到 Git，但会完整打包到 APK，安装后无需下载。
运行时文件位于 noBackupFilesDir；仅首次安装或文件校验失败时解包。

llama.cpp 为固定的 b11632 子模块。Suzu 模型推理层来自 `1zumiii/suzu-ime` 的固定提交，见 `third_party/suzu/README.md`。
上游推理层按 GPL-3.0，本次集成代码按 GPL-3.0-or-later；原有 Fcitx 文件保留原 SPDX 声明，组合分发遵守 GPL-3.0。
Suzu-2.4 权重由 IzumiThe3rd 发布，按 CC BY-SA 4.0 使用；署名、来源和许可文件随 APK 打包在 `assets/suzu/`。
本项目未修改模型权重。

## 验证

`SuzuRerankingTest` 使用 APK 内的真实模型和 Fcitx 拼音候选，检查：模型就绪、实际打分和重排、
候选池不变、点击式选择和空格上屏一致、关闭和空上文回退，以及密码/无痕等编辑框策略。
它使用合成测试句子，不依赖个人输入数据。

Gboard 第一阶段浅色主题已内置并作为新安装的浅色默认主题。原有已保存的主题设置继续生效。
