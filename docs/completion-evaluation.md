# 续写评分与评测

## 当前策略

使用 Qwen3.5-0.8B-Base Q4_K_M，相同权重、相同前文，默认保守策略。
所有概率来自未经 top-k 或多样性筛选的全词表 softmax；它们表示模型下一步选择该 token 的概率，不是文本正确率。

| 建议强度 | 起点概率下限 | 后续 token 下限 | 起点相对最高分下限 | 单字符起点下限 |
| --- | ---: | ---: | ---: | ---: |
| 保守（默认） | 0.15 | 0.40 | 0.35 倍 | 0.50 |
| 均衡 | 0.10 | 0.30 | 0.25 倍 | 0.40 |
| 宽松 | 0.04 | 0.20 | 0.15 倍 | 0.30 |

起点不合格就不建立分支，后续概率不足就停在追加该 token 之前。
通常保留至少两个字符；单字符只有满足更高门槛才保留。最多三条、每条最多八个 Unicode 字符，数量可为零。
结构标点先按相应后续概率门槛处理，再判断文字起点；诊断中的 `bridge_probabilities` 记录这些标点的分数。
`root_p` 是文字起点在该上下文下的条件概率，`joint_p` 包含已生成结构标点和文字的路径概率。

这些是初始工程门槛，尚未在独立聊天语料上校准。提高门槛会牺牲覆盖率，也不能排除模型高分接错。
概率口径参考 [Transformers 生成分数文档](https://huggingface.co/docs/transformers/main_classes/text_generation)；概率与正确率的区别见[置信度校准研究](https://arxiv.org/abs/1706.04599)。

## 固定答案诊断

选择八首常见古诗的上一句，每句分别带/不带逗号，共十六个输入；只把上一句输入模型，不提供作者、下一句或提示模板。
原 0.3.1 解码仅增加数值评分记录作为基线，不改变 token 选择。新策略采用相同 GGUF、温度和推理后端。

| 首选结果（共 16 个输入） | 完整正确 | 部分正确 | 接错 | 不显示 |
| --- | ---: | ---: | ---: | ---: |
| 原 0.3.1 | 6 | 0 | 10 | 0 |
| 保守 | 10 | 0 | 0 | 6 |
| 均衡 | 12 | 0 | 0 | 4 |
| 宽松 | 12 | 0 | 4 | 0 |

原版全部四十八条候选中有四十一条接错；保守策略共展示十条，均衡共展示十二条。
原版不带标点的八组首选全部错误：解码跳过模型首选的高概率标点，强行选了低概率词；新版先处理这些标点。
例如“春眠不觉晓”可以续成“，处处闻啼鸟。”。
“床前明月光，”的正确起点概率约 0.107，保守策略仍会不显示，均衡才保留；“白日依山尽”等模型仍接不好的输入则不算学会。

这是开发期使用的小样本，不是独立测试集，也不代表日常聊天或整体准确率。
模型、过滤器、字符上限都影响结果；不能把剩余候选中零错误写成“100% 准确率”。

## 统计口径与复现

- `exact`：忽略标点及空白后，完整匹配下一句。
- `correct_partial`：仅匹配下一句开头，不计为完整正确。
- `overrun`：先匹配完整下一句，再多写其他内容，单独统计。
- `wrong`：与下一句不匹配。
- `abstain`：实际完成推理并选择不展示；超时、取消和推理错误另记，不能当作拒答改善。
- 分开看首选结果和所有候选；聊天续写具有多解，未标注样例只观察输出，不统计准确率。

仪器测试 `QwenConfidenceEvaluationTest` 输出应用私有目录 `files/qwen-confidence-evaluation.json`。
分别保存改前/改后诊断结果后运行：

```text
python scripts/summarize-completion-quality.py baseline.json after.json --output quality-summary.json
```

原始测试输出、用户提供的探针文字、设备记录及截图保存在本地，不提交到公共仓库。
每日性能日志只保存数值与停止原因，不保存输入、候选文本或 token ID。
